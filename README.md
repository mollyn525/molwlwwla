## 示例兼容TXT

每次导出ZIP在各尝试目录附`TXT/yyyyMMddHHmmss.txt`、`TXT/source-times.csv`及`TXT/format.json`。TXT匹配用户示例的27列表头、Tab分隔、UTF-8无BOM、CRLF换行、毫秒时间；一次实际收到且已确认含惯性数据的帧生成一行，加速度/角速度3位、角度2位、四元数5位。按已核对原版Android APK的`TextRecorder.onUpdate`逻辑使用该设备最新字段快照：磁场/四元数可能复用早先回包值，来源时间表明确记录对应接收时间及500ms过期标志。TXT是派生兼容表，不用于计帧/Hz验收，也不能证明同步；原始数据不修改、不插值。

原始0x61帧的角度按signed16×180/32768换算；磁场按原版支持的0x72类型2/3/4/5/6/7换算μT，未知类型写null，原始寄存器值仍在CSV。新连接只额外读一次0x72，超时跳过不阻止惯性初始化。温度只有已记录到对应0x40帧才填写；位移、速度、电量未采集则null，不从其他受试者或名册推测。设备名称括号内使用iOS UUID而非伪造MAC。新记录保留时区偏移；旧记录缺少偏移时使用导出设备本地时区并在format.json说明。TXT包含倒计时和动作段，来源表phase区分，质量统计仍只看实际动作段。

以 Android `baduanjin_wit` 0.1.10-wit.1 为功能基线，在已有 iOS 0.1.1 上扩展；不重写协议，不删除历史数据，不修改安卓工程。Bundle ID 仍为 `dev.imulink.baduanjin.ios`，名称“八段锦采集”。SwiftUI、CoreBluetooth、Foundation/CryptoKit，最低 iOS 17，无第三方运行库。

本版本新增代码的编译、测试、安装状态必须以对应提交的 Actions 和本地交付报告为准。功能可用不等于全部硬件验收完成。前一版 0.1.1 已由用户确认 iPhone 16 / iOS 26.0.1 上 15 台初始化完成，实际导出 ZIP 已独立核对：15 台加速度/角速度约 49.63–49.67 Hz，磁场/四元数约 7.85–7.88 Hz，未通过当时四项30Hz标准。0.2.1按用户要求更改质量规则，不代表提高了实际接收率或重新验收了硬件。

## 正式门限和科学口径

正式开始需：选中的15台设备实际连接并就绪，标识互不重复，每台加速度与角速度近10秒平均接收率各>40Hz。绑定、配置模板、连续健康进度、佩戴确认与参考姿态不足均作为提醒，不阻止开始。仍须有效任务与动作编号、正常连接模式、蓝牙和服务状态可用、剩余空间>=256MiB、历史分类有效、无其他操作冲突。

动作段质量分母包含首尾和中间断流时间，不删除缺口或填补数据。每台加速度、角速度整段平均均>40Hz；两项>=500ms间隙、断线、解析或写盘错误仍否决合格。界面显示两项Hz、最长间隙和完整1秒窗未超过40帧的次数；全部四项统计仍导出。诊断独立保存。绿色只代表连接及近期加速度/角速度更新，不代表频率、佩戴或精度合格。

手机接收时间不能证明传感器四项内部同步或15台间同步；四元数范数正常不等于姿态正确。iOS设备标识是CoreBluetooth UUID，不是MAC，跨平台需要重新核对贴纸和绑定。

## 配置和校准边界

只允许已核实固件 `10080.1.21` / `10080.1.22` 的配置/校准写入。校准需看机身坐标，原始Z正向朝上约+1g，不能按外壳正面判断。App先说明姿态并要求确认，明确每台约16–20秒、全组预计保持时长；逐台过程全组保持不动。真实iPhone校准尚需单独验证，本次软件自动测试使用虚拟端口，不向IMU发送命令。

按安卓维特适配版已核实路径：`FF AA 69 88 B5` 解锁，`FF AA 01 01 00` 启动，等待至少约10.8秒（从启动的本地提交完成起），保存前复核通过才发 `FF AA 00 00 00`；不在保存前第二次解锁。继续等待并采集新的静态窗口、回读配置。移动、缺口、连接身份变化、后台切换或审计错误停止后续指令。已提交的硬件指令不能自动撤销，结果保留。

CoreBluetooth `canSendWriteWithoutResponse` 只表示本地允许提交；没有厂商执行完成应答。操作日志区分意图、提交、回读、静态复核；不得由发送成功宣称校准完成。静态门限约±0.05g属于粗略复核，不是绝对精度认证。磁场校准、归零、恢复出厂和固件升级不开放。

每次记录包含 `notifications.jsonl`、`samples.csv`、`relative_pose.csv`、`metadata.json`、`events.jsonl`、`summary.json`。复核保存到 `action-review.json`，不改原始摘要。导出另附有效计数、完整性检查、文件哈希、导出时任务/绑定快照及操作审计。统计进度应使用collection-index的counted_for_slot，不能仅看原始summary.accepted。

异常退出缺少摘要时恢复为incomplete_process_exit，不占合格次数。操作异常退出保留审计，提示硬件可能已修改，不自动恢复指令。队列上限8000，录制低于64MiB结束记异常。ZIP32单包上限4GiB，超限或取消保留原记录，不分享不完整包。
